# AGENTS.md

Instructions for coding agents working **on the TraceSpec repository itself** (not for projects that use TraceSpec; those are covered by
`SKILL.md`). Humans should read [CONTRIBUTING.md](CONTRIBUTING.md); everything there applies to you too.

## What this repository is

TraceSpec is a Claude Code skill plus Python tools: an automated requirements traceability matrix combined with acceptance-test-driven
development, run by agents. The root of the repository is the skill folder (`SKILL.md`, `process.md`, `workflows/`, `templates/`,
`tools/`), plus `install.py`, `docs/`, `examples/` and `scripts/`.

## Commands

```bash
cd tools && python -m unittest discover -s . -p "test_*.py"     # all tests; run before every commit
python tools/check.py --version                                   # the version
python install.py --claude-dir /tmp/some-dir                      # try the installer without touching ~/.claude
```

Requires Python 3.10+. Do not add dependencies.

## Rules

- **Standard library only**, no network access, no telemetry.
- **A check derives its verdict from files, git or a real test run.** Never from model judgement.
- **Every finding code needs two tests**: one that triggers it, one for the clean case.
- **Keep output ASCII-safe.** Windows consoles break on stray unicode.
- **Do not hand-edit generated or protected material** in a project that uses TraceSpec (`.tracespec/`, `docs/features/`): the tools
  write them. In this repository, `examples/shop/` is generated by `scripts/make_example.py`; regenerate it, do not edit it.
- **Update the docs in the same change**: `SKILL.md`, `docs/commands.md`, and a line under *Unreleased* in `CHANGELOG.md` when users
  will notice.
- Tests create temporary projects; they must clean up after themselves and must not touch your real `~/.claude`.
- Line endings are LF (see `.gitattributes`). When a test needs an exact file size or content, write bytes, not text, so Windows does
  not rewrite `\n` as `\r\n`.

## Before you say you are done

1. Run the full test suite and report the result truthfully, including failures and skipped tests.
2. If you changed a workflow or a template, run `python scripts/make_example.py --check` to confirm the example project still audits
   clean.
3. State what you could not verify (another OS, another Python version).
4. In your pull request, name the agent and model you used.
